# CareerForge

An AI-powered career quiz for first-year CS students. Answer 10 questions,
get a personalized tech-career recommendation (roadmap, salary range, switch
paths) generated by Gemini, sign in with Clerk, and revisit past results from
your history.

This is a standalone export: a single Vite + React frontend, a small Express
API, and MongoDB for storage. It runs locally with one command and deploys to
Vercel as-is (static frontend + serverless API function).

## Stack

- **Frontend:** React + Vite + TypeScript, Tailwind CSS v4, wouter (routing),
  TanStack Query
- **Backend:** Express + Mongoose, wrapped as a Vercel serverless function in
  production
- **Auth:** Clerk (Google sign-in)
- **Database:** MongoDB
- **AI:** Google Gemini (`gemini-2.0-flash`)

## 1. Prerequisites

- Node.js 20+
- A [Clerk](https://dashboard.clerk.com) account (free tier is fine)
- A MongoDB database — [MongoDB Atlas](https://www.mongodb.com/atlas) has a
  free tier, or use any reachable MongoDB instance
- A [Gemini API key](https://aistudio.google.com/app/apikey) (free tier is
  fine — this funds every new user's first free analysis)

## 2. Set up Clerk

1. Create an application at https://dashboard.clerk.com.
2. Under **User & Authentication → Social Connections**, enable **Google**.
3. Go to **API Keys** and copy the **Publishable key** and **Secret key**.
4. If you plan to deploy to a custom domain, add that domain under
   **Domains** in the Clerk dashboard once you know it (you can also do this
   after your first deploy — Clerk will show you the exact DNS/verification
   steps).

## 3. Configure environment variables

Copy the example file and fill in your values:

```bash
cp .env.example .env
```

| Variable                     | Description                                                           |
| ---------------------------- | --------------------------------------------------------------------- |
| `VITE_CLERK_PUBLISHABLE_KEY` | Clerk publishable key (used by the browser)                           |
| `CLERK_PUBLISHABLE_KEY`      | Same Clerk publishable key (used by the server)                       |
| `CLERK_SECRET_KEY`           | Clerk secret key (server only — never expose this)                    |
| `MONGODB_URL`                | MongoDB connection string                                             |
| `GEMINI_API_KEY`             | Gemini API key used for each user's free trial analysis               |
| `SESSION_SECRET`             | Any long random string — encrypts users' personal Gemini keys at rest |
| `PORT`                       | Local Vite dev server port (default `5173`)                           |
| `API_PORT`                   | Local Express API port (default `3001`)                               |

Generate a `SESSION_SECRET` with:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

## 4. Run locally

```bash
npm install
npm run dev
```

This starts the Express API on `http://localhost:3001` and the Vite dev
server on `http://localhost:5173` (which proxies `/api/*` to the Express
server, so the browser sees everything as same-origin). Open
`http://localhost:5173`.

Other scripts:

- `npm run build` — builds the frontend into `dist/public`
- `npm start` — runs the Express server against a production build (use
  after `npm run build`; the API itself needs no build step)
- `npm run typecheck` — type-checks the whole project (frontend + server)

## 5. Deploy to Vercel

This repo is pre-configured for Vercel (`vercel.json`):

- The Vite frontend builds to `dist/public` and is served statically.
- `api/index.ts` wraps the same Express app as a serverless function; all
  `/api/*` requests are rewritten to it, so it runs on the same domain as the
  frontend — no CORS configuration needed.

Steps:

1. Push this project to a GitHub repo (or run `vercel` from this directory
   with the [Vercel CLI](https://vercel.com/docs/cli)).
2. Import the repo in the [Vercel dashboard](https://vercel.com/new).
3. Add all the variables from `.env.example` under **Project Settings →
   Environment Variables** (use your real values, not the placeholders).
4. Deploy.
5. Once you have your `*.vercel.app` URL (or a custom domain), add it to your
   Clerk application's allowed domains if Clerk's dashboard prompts you to.

### Notes on the Vercel deployment

- MongoDB connections are cached across warm serverless invocations
  (`server/lib/mongo.ts`), which is the standard pattern for using Mongoose
  in a serverless environment. Cold starts will pay a one-time connection
  cost.
- Vercel's free/hobby plan enforces a serverless function execution time
  limit; Gemini calls for career analysis usually finish well within it, but
  if you see timeouts under load, check your plan's limit.
- If you outgrow Vercel's serverless model for the API (e.g. you need
  WebSockets, longer-running jobs, or more control), the `server/` directory
  is a normal Express app — it can be deployed as-is to Render, Railway,
  Fly.io, or any Node host without changes; just point the frontend's
  requests there instead of relying on the same-domain rewrite.

## Project structure

```
src/            Frontend (React + Vite)
server/         Express API (shared by local dev and Vercel)
api/index.ts    Vercel serverless entry point (wraps server/app.ts)
vercel.json     Vercel build + routing configuration
```

## How the free trial / BYOK flow works

- Every new user gets **1 free career analysis**, funded by the app's own
  `GEMINI_API_KEY`.
- After that, the quiz results screen prompts them to connect their own
  Gemini API key (get one free at
  https://aistudio.google.com/app/apikey).
- Personal keys are encrypted at rest with AES-256-GCM (derived from
  `SESSION_SECRET`) and are **never** returned to the browser — only a
  `hasApiKey` boolean status is exposed via `/api/account/api-key`.
